One in ten sites that publish a guide for AI also ban the readers

How many sites publish an llms.txt has been counted several times this year. This is the next question: of the 123 files found among the 1,500 most visited sites, 13 belong to sites whose robots.txt bans, by name, a crawler that would read them — and 13.5% of the files point at least one link at a page that is gone. Half the security.txt files at the top of the web are invalid

A security.txt tells a researcher where to report a hole in your site, and RFC 9116 makes its Expires field mandatory — an expired file is, in the words of the specification, as good as no file. Of the 158 such files among the 500 most visited sites, 92 carry no Expires at all and 6 have expired: 62% are not valid. Nothing warns when that happens.

A census of 5,356 live Shopify storefronts

Google and Shopify published the Universal Commerce Protocol so an agent can read a shop and buy from it. Nobody had published a count of how many shops actually speak it, so I measured it: 98.9% publish a valid profile, every one of them on the current release, none with a blocker. The only thing they differ on is whether an agent may sign the shopper into their own account — and 47.5% do not allow it, which turns a returning customer into an anonymous visitor.

AI, measured

model-eol

On 23 October 2026 OpenAI retires eighteen model identifiers in one day, five days after four more go on 28 September. GitHub code search puts 96,640 files on gpt-4-0613 alone. Every one is a hardcoded string that starts returning an error on a published date, and nothing warns first. This answers the question that comes before “how do I migrate”: does it affect me, and how long have I got. One run, no key, exit 1 for CI — and it will not flag gpt-4o as dead just because gpt-4 is.

agent-hijack-bench

An llms.txt is a file a site publishes so that an assistant will read it. This measures how often a model used as an agent obeys an instruction planted in that file instead of your request. Nineteen local models, temperature 0, scored by a canary substring so no judge model is involved — and a control case that voids a model's numbers if it emits the canary unprompted. The data-exfiltration framing beats twelve of the thirteen hijackable models every single time; parameter count predicts nothing; a published mitigation helps ten models and makes two measurably worse.

Python19 testscontrol groupruns offline

embed-drift

When a provider swaps the embedding model under a live vector index, nothing raises an error — the nearest neighbours are simply wrong from then on, and the blame lands on the language model rather than the retrieval step. This pins a fingerprint and reports two numbers: vector drift catches any change including a harmless renormalisation, while drift in the geometry between probes only moves when retrieval will actually return different rows.

Python18 testsno dependenciesexit 1 on drift

llm-doc-extractor

Every company does the same loop: open a PDF or an email, find a handful of fields, type them into something structured. This does that loop once, repeatably — you describe the fields in YAML and get exactly those keys back, across Anthropic, OpenAI or a local Ollama model with one flag. The part that matters is the failure: a reply that does not fit the schema is caught, reported and retried against the declared shape rather than written downstream. A built-in demo provider runs the whole pipeline with no API key at all.

ai-visibility-audit

An assistant's crawler fetches HTML and stops: no JavaScript, no inference. A site built for Google can be invisible to it while every SEO tool calls the site fine — a robots.txt copied from a template blocks GPTBot by name, or the page ships forty words of markup behind nine hundred kilobytes of script. Reads robots.txt per named crawler, follows the links an llms.txt promises, and judges each page on what is in the HTML. 31 of 31 offline self-checks pass.

loan-tape-import

A lender exports a loan tape and sends it again — tomorrow, twice in one day, sometimes with one field corrected and the rows in a different order. Any system fed by someone else's export has this problem, and getting it wrong means a ledger nobody can reconcile. Three levels of repeat detection, cheapest first; a corrected field writes a correction event and one history row per change instead of a silent no-op; rows that do not parse go to quarantine. 28 self-checks on the import and 28 graded cases on the classifier, both green.

well-known-audit

A site publishes a dozen small files at its root — security.txt, robots.txt, llms.txt, assetlinks.json, mta-sts.txt — each checked by a different tool or by nobody. This reads all of them in one run and says which are missing, malformed, or quietly expired. RFC 9116 gives security.txt an Expires date; past it, the file is no longer valid, and almost nobody notices.

How I work

  • The boring part is the product. Error handling, retries, de-duplication and the alert that fires when a workflow goes quiet are what make an automation worth paying for; the happy path is the easy half.
  • Claims come with the script that proves them. A number in a README that cannot be reproduced is worth less than no number.
  • Every tool documents its limits. Knowing where something stops being reliable is the difference between a tool and a liability.
  • Credentials never travel in the work. Secrets are redacted before anything is written to disk, and no repository here holds one.
