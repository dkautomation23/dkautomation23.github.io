n8n-workflow-reliability-kit

The layer production n8n instances are missing

An n8n automation fails in one of two ways: loudly, or by quietly not running any more. The second is worse, and nothing in a default install tells you it happened. Three importable workflows cover the gap — normalise a failure and route it to an alert, catch the workflow that stopped, and prove the alert route works before you need it.

Source on GitHub Work with me

What it does

  • The heartbeat is the point: a workflow that stops firing produces no error, so absence has to be watched for deliberately.
  • Failures are normalised before they are sent, so an alert names the workflow, the node and the input instead of pasting a stack trace.
  • The third workflow exists to test the other two — an alert route nobody has fired is a guess.

How it is proved

A validator in CI checks all three exports and the configuration contract the README documents: 3 workflow exports validated, README contract passed.
